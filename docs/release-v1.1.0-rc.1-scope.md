# v1.1.0-rc.1 阶段目标与冻结范围

目标：以可验证的叙事状态一致性为本阶段终点，整理上个本地里程碑后累计完成的功能，完成验收后提交并推送 GitHub，避免继续积累未提交工作。

## 本阶段必须完成

1. 承诺的待协商、已承诺、已执行分别记录；已有条件不可由 NPC 单方改写。
2. 根据物品名称、持有人、位置、容器和近邻先行词解析代称；无法唯一判断时不猜测移动。
3. 生成前注入已确认条件，提交前检查新增门槛。可识别的违规回复最多修正一次；仍不通过则不提交。流式展示不泄露被拒绝的草稿。
4. 冻结最终叙事代码后，以现有角色卡和预设新建隔离会话，以明确 NPC 留场的连续柜台交接为受控场景，重新生成多轮对话；每轮保存并重新读取，检查正文、物品和承诺。原文重放只能作为补充。
5. 全量测试、兼容测试、仓库内容检查、版本一致性、隔离备份恢复及干净工作区签发通过；整理候选版说明后推送阶段成果。

## 累计改动纳入范围

- 原卡与预设优先的提示词执行、宏展开、预算与世界书位置处理。
- 主角身份、场景连续性、时间统一、离场事实、历史修复与回合快照。
- 角色卡/世界书/预设导入评估、脚本审批、轻前端和重前端兼容边界。
- Provider 路由、后台维护、可选 Pi 运行时与对照验证工具。
- 前端工作台、开局和对话/状态展示，以及对应测试和文档。

本次从本地 `8a59412`（本地标签 `v1.0.0-milestone`）继续；远程主分支此前为 `027a932`。应用原先显示 `0.6.0-rc.1`，本候选统一显示 `1.1.0-rc.1`。数据 schema 保持 v3。

## 验收边界与后续目标

不在本阶段宣称所有社区动态脚本、任意长程指代、多层容器或完整契约推理已解决。叙事校验是有范围的证据检查，不是对任意模型输出的正确性证明。明确限制旧引擎版本的第三方插件/内容包仍按其声明处理，不能因升级而自动解除限制。

后续优先级：扩充不同卡和模型的长期样本、复杂义务与到期状态、约定关联范围与离场协调、指代歧义的交互提示、性能与完整发布治理。新增目标进入下一阶段，不滚入本候选的完成条件。

所有真实角色卡、预设、对话、API 请求响应、密钥与备份只保存在本机。GitHub 只包含框架、合成测试、验证方法与脱敏结果摘要。

实测新增边界：未限定留场的会话中，模型安排保管人提前外出，取回请求因此被拖延。该记录保留为开放剧情未通过样本，受控交接结果不覆盖这一问题；下一阶段纳入承诺可执行性与角色离场之间的协调。
