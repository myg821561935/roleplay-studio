## 一、产品定位

角色剧场是面向个人创作的本地叙事创作、角色扮演与世界模拟引擎，不是普通聊天壳，也不是 SillyTavern 的代码复刻。

核心链路：

```text
剧本书架
  -> 选择内置剧本或创建自定义世界
  -> 组装角色卡、世界书和 Prompt 预设
  -> 兼容性评定与冲突检查
  -> 主角塑造与天命选择
  -> 生成故事开头
  -> 持续对话、分支、记忆和世界状态演化
```

项目的差异化方向：

- 剧本内容包是系统主轴，不以孤立角色卡为中心。
- 角色、世界、Prompt、记忆、状态与模型相互解耦。
- 长篇叙事需要分层记忆、事实卡、事件账本和可审阅状态。
- NPC 具有目标、信息边界、关系、日程和幕后行动。
- 世界规则即使主角不介入也可以持续演化。
- 资源导入必须经过评定、入库和组装，不能直接执行未知代码。

## 二、长期设计原则

### 2.1 内容与运行边界

正式兼容定位：

> 兼容酒馆资源格式和常见交互语义，但不直接复刻酒馆的第三方扩展运行环境；第三方脚本必须经过审核、隔离和审计。

必须坚持：

- 格式兼容不等于运行时兼容。
- 安全降级必须显式提示，不能静默丢失语义。
- 没有真实脱敏样例与测试数据，不宣称覆盖率。
- 第三方 JavaScript 以本地探索、开发兼容探针或严格审批三种显式模式运行；明确拒绝、撤销、内容哈希变化或策略版本变化始终立即停止当前脚本。
- 本地探索与严格审批只能在无父页面权限、默认禁止联网的隔离沙箱中运行，并写入本地执行审计。
- 开发兼容探针只为本地角色卡调试开放子 iframe 的外部资源、网络、表单、嵌套页面和 Worker；不开放主页面 DOM、存档、Cookie、Provider 密钥、本机进程或 MCP，并审计启动、加载与错误。
- 允许安全 EJS 子集、声明式正则、Quick Reply、MVU patch 和有预算的生命周期事件。
- 社区资源原件只读；本地修改形成派生副本。

兼容性评定使用四种正式结论：

1. **完整映射**：主要行为与登记样例一致，自动化断言通过。
2. **安全降级**：保留静态内容，禁用不安全部分，并明确列出差异。
3. **本地探索 / 开发兼容探针**：存在受支持的沙箱候选；前者默认无网络，后者只为本地调试开放隔离子页面的浏览器能力，并记录执行审计。
4. **待人工审核**：严格模式下必须逐条审核并绑定当前内容哈希。
5. **阻断运行**：依赖未实现宿主、沙箱外 DOM/本机权限或存在不可控递归，只允许保存审阅。

### 2.2 内容仓库边界

- GitHub 发布技术框架、协议、测试、格式规范和最小演示内容。
- 不上传用户 API Key、本地配置、对话存档、社区角色卡、世界书、预设和作者立绘。
- 导入内容保存在本机 `data/`，提交前执行 `npm run repository:check`。
- 尊重资源作者的授权、转载和再发布要求。

### 2.3 UI 边界

- 先选剧本，再进入独立故事工程。
- 进入故事后，不持续展示其他剧本；切换剧本从固定入口完成。
- 自定义剧本使用独立向导，不把完整创建表单堆在书架首页。
- 创作模式显示组装和检查工具；沉浸模式聚焦正文、选项、输入和状态入口。
- “界面皮肤”“故事题材”“舞台背景”是三个独立概念。
- 舞台背景不得被主题滤镜强制变灰或改变色相。
- 主角信息、互动角色、世界规则、故事线索和导演注记放入侧栏，不混入正文。
- 原始 JSON、调试数据和模型控制块默认隐藏。

## 三、已经完成的能力

### 3.1 剧本与开局

- 剧本书架、卡片/列表展示、搜索和题材分类。
- 继续已有故事、独立故事工程、剧本修改和删除。
- 内置题材包括玄幻、仙侠、民俗灵异、明末历史、英雄志群像等。
- 自定义世界可从素材中心选择角色卡、世界书和 Prompt 预设。
- 开局卷宗、主角塑造、天命选择、生成开场和进入第一幕。
- 角色卡自带背景、人物信息、开场白和世界书优先于通用题材随机项。

### 3.2 角色与资源

- Character Card V2/V3 JSON 与 PNG 元数据导入。
- 大型 PNG 分阶段上传、图片元数据剥离和立绘持久化。
- SillyTavern 世界书和 Prompt 预设导入。
- 预设与配套正则的组合管理。
- 角色卡图片可作为人物立绘或故事舞台背景。
- 素材中心支持评定、入库、收藏、分类、编辑、删除、批量组织和重新评估。
- 创建新剧本时优先使用已入库资源，无需反复从文件系统导入。

### 3.3 酒馆轻前端兼容

- 安全正则显示/Prompt 变换。
- `{{char}}`、`{{user}}` 和有限宏展开。
- Quick Reply 与推荐行动。
- MVU 声明式状态及版本化 patch。
- 有预算的 `onImport`、`onUser`、`onAssistant` 生命周期。
- 常见静态重前端状态面板转换为原生侧栏卡片。
- 兼容性基准样例覆盖纯文本、正则、Quick Reply、MVU、静态重前端和动态阻断卡。

当前脚本边界：

- 默认“本地观察”模式下，可隔离的第三方 JavaScript 会在无网络隔离沙箱中运行并记录；可显式切换为仅供本地调试的“开发兼容探针”，或切换为要求人工审核与当前内容哈希绑定的严格模式。
- 审核授权、拒绝、撤销和执行尝试保存在本地会话审计中。
- 任意 EJS 代码仍不会直接执行，只支持只读安全子集。
- 脚本不能访问父页面 DOM、Cookie 或 localStorage；本地探索与严格审批默认禁止联网和嵌套 iframe。开发兼容探针允许子 iframe 使用这些浏览器能力以测量兼容缺口，但不会提供宿主权限、存档或任何 API 密钥。
- 已明确拒绝、已撤销、请求沙箱外权限或无法进入受控隔离运行时的脚本不会执行；严格模式下未审核或哈希变化的脚本同样不会执行。

### 3.4 对话与创作控制

- SSE 流式输出。
- Enter 发送、Shift+Enter 换行。
- 消息编辑、重生成、Swipe、删除和加书签。
- 推荐行动可点击，并扩写为符合当前主角、环境和场景的行动。
- “继续推进”使用隐藏导演命令，不显示成玩家对白。
- 用户离开底部阅读时，流式生成不会强制拉动滚动位置。
- Markdown 正文、天机选项和原生选择按钮。
- 角色卡语气、示例对话和近回合角色锚点优先于通用题材文风。

### 3.5 记忆与世界状态

- 最近对话、滚动摘要、未总结轮次。
- `MemoryService` 统一编排情节记忆、向量召回、摘要和图谱上下文；不建立第二套事实源。
- 情节记忆记录证据消息、分支、修订号和有效期；编辑、重生成与 Swipe 后会重放并失效放弃分支。
- 摘要维护同时产生滚动摘要和独立 Scene；4 个 Scene 晋升 Chapter，3 个 Chapter 晋升 Arc。所有层级引用下级修订号，旧分支和旧 Swipe 摘要不会继续召回。
- 动态事实提取、事实卡审阅和提升为世界书。
- 世界状态、关系、物品、伤势、地点、主线和事件账本。
- NPC 公开/私有信息、目标、日程、议程和幕后事件。
- 世界时钟和声明式动作裁定。
- 分支重生成后可以重放选中分支的状态效果。
- 原始 CoT 仅是模型临时推演，不显示、不持久化、也不作为事实；需要保留时只写入带证据和可信度的决策摘要。详见 `docs/memory-system-v1.md`。

### 3.6 结构化世界系统

世界书会转换为 `narrative-engine.world-systems/v1`：

```text
topology     地点节点、显式连接、当前位置
population   NPC 档案、日程规则
factions     势力实体、关系
calendar     历法、时代、日期标签、天候规则
economy      货币、市场、物价和税率规则
cultivation  修行路径、刻度、反噬和修炼规则
```

分类依据包括标题、关键词、类别、扩展字段和静态正文。系统只提取明确关系，不凭空编造地点连接或势力关系。

模型输出中的 `<think>`、`<analysis>`、`<descriptive_analysis>` 和社区 `<ai_last_output>` 控制块不会进入可见正文；可用信息转入右侧“导演注记”卡片。

### 3.7 Provider 与本地治理

- OpenAI-compatible、DeepSeek、Anthropic、Gemini 和自定义模型。
- Provider 厂家与模型候选联动。
- 测试连接、凭据遮罩、按会话绑定 Provider。
- Token 用量统计和后台任务归属。
- 一键备份、恢复、数据版本迁移。
- 本地启动、停止和重启脚本。

长期模型路线：

```text
世界管理/记忆模型  -> 便宜、稳定的结构化模型
普通 NPC 模型      -> 低成本模型
核心角色模型       -> 高质量文学与角色模型
导演/检查模型      -> 规则检查、调度和剧情规划
```

角色资产不得绑定某一家模型。
