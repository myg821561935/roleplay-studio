# 仓库内容边界

本仓库用于发布 Roleplay Studio（角色剧场，仓库名：`roleplay-studio`）的技术框架，不承担第三方角色卡、世界书、Prompt、图片或完整内容包的再分发。

## 可以进入 GitHub

- 前后端源码、测试、数据迁移和启动脚本。
- Character Card、World Book、内容包与插件的格式规范。
- 不包含私人创作内容的最小测试夹具。
- 项目自行创作，或获得明确公开授权的内置演示内容。
- 自行生成且确认可公开使用的界面背景资源。

## 只能保存在本机

- 从类脑、Discord、SillyTavern 社区或其他站点下载的原始角色卡和世界书。
- 卡片内嵌立绘、头像、音频、前端文件、正则、数据库和作者预设。
- 基于第三方资源生成的派生角色、独立副本和组合剧本。
- 用户实际使用的角色卡、世界书、Prompt、Provider 配置、会话、记忆和故事工程。
- 作者没有明确允许转载、二传或公开再分发的任何内容。

这些内容应由应用写入 `data/config/`、`data/library/`、`data/assets/`、`data/projects/` 等本机目录，或由用户手工放入 `data/content-packs-local/`。这些目录不会进入 Git。

## 内置内容包

`data/content-packs/` 是公开发布区域，不是个人素材目录。向其中新增内容前必须确认：

1. 内容由项目自行创作，或原作者明确允许以当前许可证公开再分发。
2. `README.md` 标明用途、作者和许可证。
3. `sources.md` 记录参考来源及授权边界。
4. 不包含从社区卡中直接复制的角色、世界书正文、图片或前端代码。

不满足以上条件时，应创建本机独立副本，而不是提交到该目录。

## 提交检查

提交前执行：

```bash
npm run repository:check
```

该命令检查已跟踪文件和暂存新增文件。如果发现本机配置、社区素材、故事存档或私有内容目录，会阻止发布检查。`npm run release:check` 已包含此步骤。
