# 主角身份与场景连续性修复

本次优先处理姓名占位符、人物离场和已完成动作在后续回合中的保留。默认执行链仍为 native，Pi 保持实验状态。

## 实现

- 主角姓名依次取启用的用户角色、历史修复中的规范姓名、世界状态中的主角姓名。没有姓名时使用“主角”等称呼，不推断人物实际名叫“无名”。单独的 `<user>`、`{{user}}`、`主角原名`在最终请求和已解析的回复展示数据中归一化；成对的 `<user>…</user>`结构标签保留。状态变更路径和脚本载荷不由展示层改写。
- `memory.sceneContinuity` 保存已接受正文中的明确动作结果、人物转场和带来源消息 ID 的场景原句。它是叙事观察记录，不是自动升级的世界设定或硬事实。
- 记录与正常回复一起提交到会话。下一轮从有效历史重新构建并在最终预算中保留，独立于可选的记忆召回开关，也不依赖最近对话窗口是否保留了来源回合。
- 隐藏、恢复、编辑和重生成通过历史重建更新记录。人物解析提示保存在来源消息上；重建仅借用姓名重新扫描当前正文，不直接恢复旧事实。隐藏、被一致性检查排除和中止的回复不作为新的完成证据。
- 人物在正文中明确离开时，在场投影不会因为心理描写、模型的旧在场名单或“朝离去的方向看”等句子将其恢复。明确返回则更新转场记录。不确定代词指向时保留原句，不强行判定角色身份。
- 用户明确要求“不采取行动”或“保持当前地点”时，最终回合校准补充对应约束，防止为推进剧情而自行返工或移动。

## 验证方式

本地测试覆盖身份来源优先级、结构标签、正文与面板归一化、控制载荷隔离、离场/返回顺序、想法/引语/计划排除、自然结果表达、长历史保留，以及真实 AgentService → SessionService → JsonStore 提交、重新读取、隐藏恢复和编辑重建。

真实模型验证使用用户指定角色卡与预设的隔离副本、开场前记忆及专用验证姓名。每轮通过正式生成和提交流程落盘，下一轮创建新的服务并重新读取会话。最终对照复用同一段已取得的真实模型开场回复并实际提交，再让 native 和 Pi 各生成两次续接；开场复用与新 API 调用在结果中分开标记。

私有验证记录位于 `work/validation/2026-09-15-continuity-commit/`，其中 `REPORT.md` 汇总最终实测结论。角色卡、预设、请求、回复和实验存档留在被版本控制忽略的本地目录。

## 尚存边界

- 自然语言抽取有明确支持范围；无明确结果、复杂代词、隐喻、多人交叉动作等可能只保留原句或无法识别，不代表完整的语义状态机。
- 已记录的历史动作不保证其结果永久有效。明确返回、新损坏或玩家主动重做需要结合后续正文判断。
- 提示词约束不能保证每次生成都不越过玩家行动范围。API 成功、状态落盘、后续请求携带记录和正文实际遵守，是四项不同的验证结果。
- 此次不扩大任意动态人设脚本、EJS 或 Tavern Helper 脚本的执行能力，不能称为动态人设脚本已全部兼容。
