# 互动节奏与控制权契约 v1

状态：已实现  
契约标识：`lra.interaction-control-contract/v1`

## 目标

本契约约束角色剧场在角色卡、世界书、社区预设和用户操作发生冲突时，如何保留玩家控制权并稳定互动节奏。它是运行时与剧本组装层的约束，不修改导入的原始角色卡或预设。

## 规范行为

### 1. 真实用户发言锚点

- “继续推进”“（请继续推进剧情）”等导演快捷指令属于控制信号，不是新的角色发言。
- 继续生成时必须找回最近一条可见、非控制信号的用户消息，并把它作为受保护的历史锚点。
- 即使最近消息预算已经被连续推进记录占满，也不得静默淘汰这条真实用户发言。

### 2. 模式边界

- `dm`（标准 DM 叙事流）：每次继续只完成一个世界反馈节拍，产生一项直接可见变化，然后在自然节点把行动权交还用户。
- `character`（角色扮演流）：只控制 NPC 与世界反馈，不代写玩家动作、对白、内心或决定。
- `protagonist`（叙事子流派）：可以描写用户已明确动作的后果，但不能新增玩家动作、对白或决定。
- `director`（导演 / 共创流）：可以补写与既有意图一致、可撤回的低风险动作和短对白；重大、不可逆、阵营、资源重押与亲密边界决策仍须交还用户。

### 3. 预设互动语义预检

剧本组装预检会从启用的预设模块中识别：

- 请求代写玩家的“抢话”语义；
- 保护玩家控制权的“别抢话”语义；
- 提高 NPC 对话密度的“对话增多”语义。

检测结果进入兼容审查指纹，并在创建剧本前显示与当前模式的冲突。预检只提示差异，不擅自修改或禁用原预设；运行时仍以实时选择的角色扮演模式裁决。

### 4. 不可静默淘汰的提示预算

以下运行时消息属于受保护项：

- 互动控制权契约；
- 当前正文输出契约；
- 最近真实用户发言锚点；
- 多角色压缩索引；
- 角色锚点与关键世界书条目。

社区预设中的互动语义还会获得额外运行优先级。即使完整预设正文因上下文预算被裁剪，压缩后的语义结论仍必须保留。

### 5. 多角色卡索引

多人卡和场景容器卡会生成一份受保护的压缩角色索引，最多保留 16 名当前可用角色的名字和最小身份线索。索引只解决“模型忘记场上有哪些人”，不能替代世界书触发：

- 详细人物背景、秘密、关系与专属规则仍按关键词或场景条件触发；
- 未触发的详细资料不得从索引中推断或编造；
- 内容分级不允许的角色条目不会进入索引。

## 角色立绘显示

对话渲染现在会优先复用角色卡中已经导入到本地的立绘：

- 主角色和启用的多人角色都可以成为消息头像；
- 正文中能识别出明确说话人的对白，会显示该角色的小头像和姓名牌；
- 仅接受本地角色图片接口，拒绝把任意外部图片 URL 注入正文；
- 无立绘或无法确定说话人时，回退到原有的姓名色标，不伪造头像。

## 后续 AI 立绘生成边界

未来可根据角色卡的外观、服饰、时代、气质与内容分级生成候选立绘，但应作为独立、可审计的派生流程：

1. 先展示生成依据与将要发送给模型的角色信息，由用户确认；
2. 仅生成到本地素材库，不覆盖原始角色卡，也不自动提交 Git；
3. 保存来源角色资源 ID、资源版本、模型、生成时间、提示词摘要哈希和人工选择记录；
4. 用户确认某个候选后，新建立绘派生版本，并允许随时回退到原卡图片；
5. 未经确认不得把私密角色卡全文或世界书秘密发送给外部图像服务。

## 验证要求

- 单元测试覆盖继续信号识别、真实用户锚点、DM 单节拍、导演模式低风险共创和预设冲突识别。
- Prompt 组装测试覆盖紧预算下的真实用户锚点与多人压缩索引。
- 资源库测试覆盖组装前 DM / 导演模式冲突差异。
- 前端测试覆盖本地主角 / 多人角色立绘映射和外部图片 URL 拒绝。
- 里程碑发布前运行全量测试。
