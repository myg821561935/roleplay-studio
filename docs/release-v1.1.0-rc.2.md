# 角色剧场 / Roleplay Studio v1.1.0-rc.2

本候选修复正常动作误拦截、持有可随时取回寄存物时的离场冲突，以及多人交接中的人物和物品指代。产品名称延续角色剧场 / Roleplay Studio。

## 变化

- 正常验看、包装和否定新增条款不作为新门槛；“能不能看清，也可以就这样拿着”不再误匹配条件句。含转折的实际新增要求仍校验。
- 明确区分直接持有人与保管责任人；正常查看时把整只匣子放到台面，不提前解除保管责任。同句多个物件的放置位置分别绑定。
- 完成交接后的“没有放进袖里”等否定只约束对应动作，不回溯否定已完成的交接。
- 保管动作已经执行不等于持续的随时取回义务结束。仍承担寄存物保管责任时，正文离场及后台日程要与约定协调；物品交还后解除约束。第三人接管需明确授权。
- 人物执行者、接收者、前者/后者、现有持有人共同限定指代；不唯一时不按最近名字猜测；新出现的路人主语不继承前一位保管人。交接不自动改变所有权。支持物品作主语的明确手到手交接，把物品放进指定人物掌心，以及接收者明确“接过某件物品”。不从玩家身上擅自取物，不把尚未接过记为完成；正文声称接收但未落实到账本时触发修正。
- 明确发生的 NPC 转场同步到人物位置；穿门离场但尚未写明去向时保留“场外、具体位置待确认”，不凭玩家请求虚构已经到达。后续明确路线可继续同步，返回时恢复在场状态。对白中的计划不当作已经发生。世界书档案刷新保留实际位置和状态，避免把已离场人物重置回常驻地。
- “交到手里”按已完成交接识别，“递向对方、等待接住”不提前完成；“不递给某人”不产生交接要求。物品已放下之后听见声音，不再误作旁观别人行动。
- 离场主体按具体分句识别，“等客人走远”不会误判保管人离场。一个请求同时提到“放回甲物、乙物不动”时，只核对实际要放回的物品；复述玩家请求不能充当完成证据。
- 同名名册条目不再使明确受托人丢失；未知受托人不会绑定无人持有的台面物品。
- 自动纠正明确给出当前持有人、接收人和完成动作句式，要求动作证据逐字引用已发生的正文，避免把“递向”或玩家请求当作已完成交接。
- 空的 plot/content 标签不再吞掉标签外的有效正文。

## 验收

- 全量自动测试：1,537 项通过；覆盖新增误拦截、保管责任、日程冲突、离场同步、多人交接、否定范围和请求证据回归。
- 最终冻结代码后，从零历史新生成两组会话：保管与离场 8 轮，多人交接与歧义 10 轮。每轮通过真实服务保存并重新读取；18 轮关键状态核对通过，无手工重试。
- 使用现有卡、预设的隔离副本，native 运行时，经已配置的 DeepSeek 官方接口使用 `deepseek-flash` 别名；未据此推断上游具体模型版本。共 31 次 API 调用（含辅助任务），5 轮自动纠正（保管 1、多人物品 4）。自动纠正仍会增加延迟；不把最终通过视为首次生成成功率。
- 核对承诺阶段、归还前后的保管责任、所有权与数量、明确交接与歧义澄清、真实离场和时钟一致性。原有角色卡、配置与测试前存档哈希保持不变。
- 诊断失败、中止、原文回归及最终验收分别保留在本机报告中。前期确实出现过误拦截和正文与账本不一致；修复后另起全新会话验收，未用重放替代 API 验证。

## 边界

不宣称通用语义或契约证明。诊断中仍观察到模型混用容器称谓、误述先前经历、扩写旁人和背景线索、临时人物性别代词漂移；最终样本仍有对白误述经手次数、确认现状被新剧情抢占的问题。关键账本通过不等于整段正文完全忠实，也不等于长程文风与角色还原全部解决。此版本聚焦已经记录的物品保管与明确动作；未结构化约定、远距离代词、复杂容器与隐含授权仍可能无法可靠识别。原有离场事实不自动改写，不以瞬移补偿历史冲突。最多一次自动修正，仍不通过则不保存。真实样本与请求响应仅留本机；数据 schema 仍为 v3。
