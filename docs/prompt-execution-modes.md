# 故事执行方式与上下文检查

会话设置提供“自动选择”“原卡优先”“Agent 增强”和上下文预算。自动选择对导入角色卡或酒馆预设使用原卡优先，其他会话沿用 Agent 增强。修改后下一轮生效，不改写历史消息。已有存档的上下文预算保持原值。

## 原卡优先

- 按原顺序完整展开已启用、符合触发条件的预设，包括临时 setvar/getvar 变量链。不再默认限于 18 个模块，也不再提前分配总预算的 30%。仅赋值、展开后为空的模块不产生模型消息，但赋值仍生效。
- 保留角色描述、性格、系统提示和完整示例。多角色场景卡不把自动补全的根卡性格、开局和示例冒充作者原设定。前置世界书保留；示例前后条目围绕独立示例块排列。
- 世界书仍经过既有激活、条件、安全编译流程。没有显式世界书预算时，完整保留本轮激活条目；用户或卡片声明预算时按整条选择并记录排除项，不截断条目内部协议。总上下文不足时保留必要历史、原卡和预设，明确报错；不会静默删除原卡规则后继续生成。
- 正文只增加简短的控制权、事实连续性与自然收束要求，不默认要求通用状态表、三个选项或隐藏回合帧。没有作者输出的行动选项时，不用通用规划器补出一组。可靠记忆按类别提供有限上下文。
- 正则若将玩家行动完全清空，保留该条行动并记录兼容调整。显示投影不受此保护规则影响。
- at-depth=0 位于当前玩家消息之后，保留世界书声明的 system/user/assistant 角色。Author’s Note/outlet 等未实现的槽位仍明确降级；本模式不代表完整执行任意酒馆插件。示例文本保留在独立 system 块，尚未完全复刻所有酒馆示例消息分段规则。

预算为本地估算，不是供应商的精确 tokenizer 计费。提高前应确认模型能容纳输入及预留输出。预算报错给出保留必要历史后的估算最低值；更大预算可以保留更多近期历史。

## Agent 增强

保留现有世界模拟、行动协议与状态呈现。导入原卡或社区预设时，增强模式也完整保留原卡字段、示例与预设变量链，不再因旧的 18 模块限制或分块预算停用整套社区预设；预算不足会明确阻止发送。纯本地素材仍使用原有预算策略。紧凑、标准、长篇的目标分别为 600–1000、1200–2000、2000–3200 中文字符；这些是参考，不要求为凑字数填充内容。继续推进也应自然结算后果，在需要玩家作决定时停止。

## 回合与工具

浏览器流式回合先持久化权威正文，再返回完成事件。长期记忆在独立快照上后台维护；每次存档写入产生唯一修订号。下一回合、编辑、设置、分支或删除使旧修订失效，过期摘要不会覆盖新存档。任务队列在进程内，不保证重启后继续执行尚未完成的维护；后续回合仍可触发维护。

MCP 使用 OpenAI 兼容接口的工具流，拼接分片工具参数，工具完成后继续流式生成。取消信号传递至模型请求与工具适配器，且阻止后续工具和模型轮次。已发出的工具能否立即停止取决于适配器。已经输出正文后发生错误，不回退到另一个模型拼接第二份答案。原生 Anthropic/Gemini 工具协议尚未实现，会明确报错，不再忽略工具参数。

## 验证边界

### 可选增强与请求检查（2026-09-09）

本局执行设置中的“可选增强”提供记忆召回、NPC 幕后活动、剧情引导和行动建议四个独立选项。每项可选择跟随模式、开启、关闭；修改后从下一轮生效。关闭记忆召回同时停止自动摘要维护，不删除存档中的记忆。NPC 开关控制自动幕后推进，不禁止角色卡明确输出的状态更新。关闭行动建议不删除作者自身输出的选项。

在“设定 → Prompt → 提示词工作室”刷新预览，展开“查看逐阶段变化”，可检查预设编译、世界书选择、宏与正则处理、预算处理及系统追加内容的前后文本。记录来自本次装配，不重复执行宏；预览不发送模型请求，也不持久化临时变量。尚不是全部社区插件执行事件的追踪器。

“导出同条件对照材料”导出同一会话快照的原卡优先与增强模式请求、历史摘要值和已配置模型信息。两组使用各自模式默认增强组合，不使用当前手动增强覆盖。该材料属于装配预览，不包含真实模型结果、外部记忆检索结果或供应商最终序列化请求，配置参数也需在实际发起对照前核对预设覆盖。酒馆参考请求必须来自酒馆实际导出，不可用本项目结果替代。固定同一模型、采样参数和历史后，各组至少重复生成三次，再隐藏来源按人物还原、文风自然、行动后果、重复铺垫、玩家控制权评分。先做固定历史单轮对照，再做各自演进的多轮体验评估。

角色卡快捷开局只携带明确选择的预设及角色配套世界书，不再自动取素材库前几个预设。完整导入兼容检查仍保留。

自动化覆盖原卡尾部字段、超过 18 段的变量链、预算不足、历史保护、角色与深度、示例位置、后台存档竞争、流式工具分片与取消、设置保存。实际写作质量仍需固定模型、采样参数、角色卡、预设和用户行动路线进行盲评。测试通过不等于已经证明优于酒馆或其他产品。

### 固定历史对照执行器

可用 `node scripts/run-roleplay-comparison.mjs <对照材料.json> <新的结果目录> --dry-run` 预检；将末尾改为 `--run` 才会访问模型服务。通过 `ROLEPLAY_COMPARE_BASE_URL`、`ROLEPLAY_COMPARE_API_KEY` 指定已授权服务和凭据，`ROLEPLAY_COMPARE_MODEL` 可覆盖模型，`ROLEPLAY_COMPARE_REPEATS` 默认为 3、范围 1–10。凭据不写入结果文件。当前执行器仅支持 OpenAI 兼容接口和纯文本单轮请求。

预检要求所有模式均可运行，并比较供应商实际请求中的非 messages 参数；例如 DeepSeek 的自动思考开关因提示词内容产生差异时，会要求先显式统一配置。执行不自动切换模型、不自动重试或修改思考模式。可选 topP、frequencyPenalty、presencePenalty、seed 如已配置，会保留并发送；未配置则不追加。此轮没有增加这些参数的页面控件。

每组默认重复三次，随机打乱请求顺序。结果目录含 `manifest.json`（进度与实际参数）、`blind.json`（匿名正文及空白评分项）、`key.private.json`（来源对应表）和各次实际请求体、原始响应。评分前只打开 blind.json；每项按 1–5 分填写，越高越好，nonRepetition 表示更少重复铺垫。原始正文可能自行暴露模式特征，所以这是隐藏来源标签的评测，不保证完全无法辨认来源。发生错误会保留已完成结果并标记 failed；重跑必须使用新目录，不能把不完整实验冒充完成结果。

此执行器不运行 Agent 工具循环或后续记忆维护；用于固定历史的提示词差异对照，不替代多轮产品体验。若未填入真实酒馆参考请求，结果明确标记没有酒馆基线。

2026-09-09 真实样本对照发现增强模式也可能被社区正则清空历史玩家输入；现在两种模式都保护非空玩家行动，恢复正则处理前的文本并记录原因。当前输入的宏仅展开一次，保护回退不会重放赋值或自增副作用。该修复不修改原始正则和存档；不拦截保留了部分文本的转换。

### 历史人称冲突提示

提示词工作室刷新预览后，如果已启用预设明确要求第三人称，但多条近期历史回复疑似使用第二人称旁白，会显示提示。常见引号中的对白、代码块和分析块排除后再检查；这只是启发式提醒，可能误报或漏报，不自动改写历史，也不影响请求发送。

2026-09-09 单故事对照中，历史旁白人称调整使后续第三人称输出从原样对照 0/3 变为 3/3；仍存在重复与玩家控制权问题。此结果不能作为通用批量改写的依据。评测执行器会将 finish_reason=length 的输出标记为截断，不作为完整回复评分。

### 生成历史人称修复副本

本地工具 `scripts/repair-history-perspective.mjs` 提供两个阶段：`preview <原会话.json> <新审阅目录> <已确认玩家名>` 生成逐条前后文本与精确替换位置；审阅后用 `apply-copy <原会话.json> <审阅目录> [副本上下文预算]` 创建新 ID 的故事副本。原会话不变。副本会同步活动回复版本并重建事件日志基线，非活动版本保持原样。

此功能尚无页面按钮，不会自动扫描或修改其他故事。标签、代码、引号异常会跳过；多人或无引号对白仍需人工审阅。来源在预览后发生变化会拒绝应用，不能用旧方案覆盖新对话。

### 写作检查与事实来源（2026-09-09）

正常回复、流式回复和续写结束时，会检查疑似替玩家追加内心、承诺或动作，以及最近四条回复中的整句重复、连续重复的前置条件。结果附带实际片段显示在运行提示中；重新生成时参考这些片段进行定向修正，并沿用原有 swipe 版本保留机制。这些规则属于保守的文字检查，不能证明角色行为越界，也不自动删除正文或替玩家确认事实。新回合只在命中规则时追加有具体依据的提示。

提示词工作室的本地预览会列出原卡、启用预设中的明确人称／格式冲突，以及历史人称偏移。可在模块列表关闭冲突模块或局部覆盖；不会擅自改写导入素材。未明确表达的文风冲突仍需人工判断。

生产事实提取链路为事实记录增加来源：原卡、用户确认、历史中出现、模型推测。模型自报 `confirmed` 不再足以自动入库：原卡或明确确认内容必须有完整语句依据；历史中出现的内容也只是候选，不能覆盖原卡。提取器提出的 World State 修改留在 `pendingWorldStateExtraction` 供检查，实际状态仍由既有行动结算维护。编辑事实或明确启用候选事实后才标注用户确认。已有历史记忆不会被批量追认或删除。

完整保留原卡的模式（包括导入资源的增强模式）在预算不足时，先移除可选的 Agent 剧情提示、动态记忆补充、群像索引等，再考虑较旧对话。原卡、预设和最小必要历史仍保持完整，无法容纳时在发送前报错。工作室显示淘汰区块和估算 token；模型实际 token 以 Provider usage 为准。

页面操作路径：设定 → Prompt → 提示词工作室 → 历史人称修复。填写已经确认的玩家姓名，点击预览，逐条检查修改前后，再创建独立修复副本；可选择仅提高副本的上下文预算。原存档变化后旧预览失效；相同预览与选项重复提交会返回同一个副本。复杂标签、代码、不完整引号仍需人工处理。
